# SEO — manual steps for the owner

These are the SEO tasks that **only you can do**: they need your Google account, Play Console, domain or business
decisions. Everything else (titles, descriptions, canonical URLs, sitemap, structured data, checks) is generated by the
build and checked automatically.

Prepared 2026-10-08 from current Google Search Central, Search Console and GitHub Pages documentation. Tick the boxes
as you go.

The site today: `https://greenplantapps.github.io/nexascan-web/` (GitHub Pages, project site).

---

## Step 1 — Decide on a custom domain (optional, but decide first)

On the current `github.io/nexascan-web/` address Google **cannot** show NexaScan's own site name or favicon in
results, robots.txt cannot be used, and only a "URL-prefix" Search Console property is possible. A custom domain
(for example `nexascan.app` or `getnexascan.com`) fixes all of these. GitHub doesn't charge for it; you pay only the
domain registrar's yearly fee.

Decide **before** Step 4. Changing the address later means a new Search Console property and new canonical URLs.

If you choose a domain:
- [ ] Buy the domain from any registrar.
- [ ] In the registrar's DNS settings add:
  - for `www.yourdomain`: a **CNAME** record → `greenplantapps.github.io`
  - for the bare domain: **A** records → `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`
    (and optionally **AAAA** → `2606:50c0:8000::153`, `2606:50c0:8001::153`, `2606:50c0:8002::153`, `2606:50c0:8003::153`)
- [ ] GitHub → `greenplantapps/nexascan-web` → **Settings › Pages › Custom domain**: enter the domain, save.
- [ ] When it becomes available (up to 24 hours), tick **Enforce HTTPS**.
- [ ] Tell Claude the domain, so `siteUrl` in `site.config.json` and every canonical URL are updated.

## Step 2 — Publish the app publicly on Google Play (blocker for "launched")

The Play listing currently returns "not found" because NexaScan is on Internal testing only.
- [ ] Release to **Production** (or **Open testing**) in Play Console.
- [ ] Copy the public listing URL (`https://play.google.com/store/apps/details?id=com.greenplant.nexascan`) once it
      opens without signing in, and give it to Claude (it goes into `storeUrl`; every download button then goes live).

## Step 3 — Link the site from the Play listing

This is the most useful genuine link the site can have.
- [ ] Play Console → **Store presence › Store settings › Store listing contact details**: set **Website** to the
      site's home page URL and **Email** to the support email.
- [ ] Play Console → **App content › Privacy policy**: set it to the site's `/privacy/` URL. Keep that URL unchanged.

## Step 4 — Add the site to Google Search Console

- [ ] Go to <https://search.google.com/search-console> and sign in with the Google account that should own the site
      data.
- [ ] **Add property**:
  - without a custom domain: choose **URL prefix** and enter `https://greenplantapps.github.io/nexascan-web/`
    (a Domain property is not possible on github.io);
  - with a custom domain: choose **Domain**, enter the domain, and add the **TXT** record Google shows to your DNS.
- [ ] For the URL-prefix property choose the **HTML tag** method and copy only the `content` value, e.g.
      `<meta name="google-site-verification" content="THIS-PART">`. Paste `THIS-PART` into `site.config.json` →
      `seo.googleSiteVerification` (or give it to Claude): the build adds the tag to the home page. Once that
      version is live, press **Verify**.
- [ ] Never remove the tag (or TXT record) afterwards. Verification is lost if it disappears.

## Step 5 — Submit the sitemap

- [ ] Search Console → **Sitemaps** → enter `sitemap.xml` (full address
      `https://greenplantapps.github.io/nexascan-web/sitemap.xml`, or `https://yourdomain/sitemap.xml`) → **Submit**.
- [ ] After a day or two check that the status says **Success**. Resubmitting is not needed after updates. Google
      re-reads the sitemap, and the build keeps its dates accurate.

## Step 6 — Request indexing (one time, optional)

Normal discovery (links + sitemap) is the standard path. Use this only for the launch.
- [ ] Search Console → **URL inspection** → paste the home page URL → **Request indexing**.
- Don't repeat it for every page. There is a daily limit, and it doesn't speed up ranking.
- This cannot be automated: the Search Console API can only *read* inspection results.

## Step 7 — Check in occasionally (5 minutes, monthly)

- [ ] **Performance**: clicks, impressions and the search terms people use. Data appears only once the site gets
      impressions.
- [ ] **Pages** (indexing): look for errors, not for "Excluded" items that are expected (for example the 404 page).
- [ ] **Core Web Vitals**: "Not enough data" is normal for a new, low-traffic site.
- Report anything unusual to Claude, or run the `nexascan-seo` skill (after Stage B) for a full check.

## Step 8 — Optional: let Claude read Search Console automatically

Needed only if you approve the optional Search Console automation. Skip otherwise.
- [ ] <https://console.cloud.google.com> → create a project (e.g. "nexascan-seo"). No billing account is needed for
      this API.
- [ ] **APIs & Services › Library** → enable **Google Search Console API**.
- [ ] **OAuth consent screen** → External, Testing mode, add your own Google account as a test user.
- [ ] **Credentials › Create credentials › OAuth client ID** → type **Desktop app** → download the JSON.
- [ ] Save it **outside the repository** (for example `D:\secrets\nexascan-gsc-client.json`). Never commit it or
      paste its contents into chat.
- [ ] Run the one-time sign-in Claude provides and approve the access. Claude never sees your password.

## Step 9 — Genuine visibility (ongoing, your judgement)

- [ ] Link the site from places you control: the Play listing (Step 3), GreenPlant Technologies' own website or
      profiles, and social accounts if you have them.
- [ ] Only list NexaScan in directories or communities where it genuinely fits.
- Never buy links, swap links in bulk, post review requests in exchange for rewards, or publish fake reviews.

---

## What not to do (any of these can harm the site)

- Don't use Google's Indexing API, sitemap "ping" or paid "instant indexing" services. They are not for this kind of
  site, and the ping service no longer exists.
- Don't add star ratings or reviews to the site unless they are real and visible to visitors.
- Don't create many near-identical keyword pages.
- Don't block pages in robots.txt to remove them from Google. Use `noindex` (Claude handles this in the build).

## What is already automatic

Page titles and descriptions, canonical URLs, the sitemap and its dates, structured data (WebSite + Organization),
the noindex on the 404 page, social preview tags, and `npm run verify` on every push and pull request, which stops
the deploy on serious SEO errors. The `nexascan-seo` Claude Code skill (`.claude/skills/nexascan-seo/`) runs the
audit and explains the results on request; it does not run on a schedule by itself.
